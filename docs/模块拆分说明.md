# WorkBuddy CLI 模块拆分说明

`extracted-app/` 是客户端发布包的编译产物，不能凭空还原成原始 TypeScript 源码。本次整理在其上增加 `packages/` 分层：每个包提供稳定的包名、可读的 `src/source/` 文件和可追溯的编译产物兼容层。

`src/source/` 保存与发布包逐字一致的 JavaScript 证据快照，不对 bundle 整体执行格式化，以免改变压缩表达式的语义。可维护的恢复代码按职责放在包内的 `src/runtime/` 等目录，并通过测试确认行为。Renderer 沿用发布时已有的 Vite/Rspack chunk 边界。

## 模块边界

| 包 | 责任 | 主要编译入口 |
| --- | --- | --- |
| `agent-ui` | Agent 对话、任务和 Artifact UI | `renderer/assets/*` |
| `agent-provider` | Agent provider 与 CLI provider | `renderer/assets/app-providers-*`, `cli/dist/codebuddy.js` |
| `agent-client-protocol` | ACP 消息与连接 | `main/acp.js`, `renderer/assets/acp-*` |
| `workbuddy-app` | Electron 主进程、Preload、Renderer 壳 | `main/index.js`, `preload/index.js` |
| `workbuddy-core` | 公共 contract、types、helpers | `main/common.js`, `main/contract*.js` |
| `workbuddy-server` | Daemon、本地服务、MCP/Connector proxy | `main/daemon-app-server-*.js`, `main/module.app-server.js` |
| `runtime` | Sidecar、运行时上下文和进程环境 | `main/sidecar-entry.js`, `main/runtime-*.js` |
| `context` | 启动上下文与上下文查看器 | `main/startup-context.js`, `renderer/assets/*context*` |
| `authentication` | 登录、凭据存储、会话迁移 | `main/auth.js`, `main/*authentication*` |
| `telemetry` | 日志、性能标记、Trace | `main/logger*.js`, `main/marks.js` |
| `enterprise-policy` | 文件保护、只读策略和审计 guard | `main/fs-protection.js`, `main/readonly.js` |
| `plugin-core` | Built-in Skill、Plugin 和 MCP App 分发 | `resources/builtin-*` |
| `sandbox-cli` | 沙箱二进制、规则与安全 shim | `cli/vendor/sandbox`, `cli/sandbox-config.json` |

已迁移的可维护适配入口：

- `agent-client-protocol/src/runtime`：NDJSON 编解码和 JSON-RPC 请求连接。
- `runtime/src/runtime`：按 Session 管理 Sidecar 子进程，恢复 Session bridge、协议路径、readiness 握手、环形输出缓冲、Runtime HTTP、运行时上下文、启动上下文传播和 CLI 环境隔离。
- `plugin-core/src/runtime`：Skill frontmatter 与 Plugin manifest 发现。
- `plugin-core/src/runtime`：Skill/Plugin manifest、深度受限安全扫描、符号链接隔离与 marketplace 合并。
- `sandbox-cli/src/runtime`：命令拒绝、可写目录和子进程执行策略。
- `authentication/src/runtime`：600 权限凭据文件和原子更新、认证会话/Headers、账号企业上下文与进程内 Gateway Secret。
- `telemetry/src/runtime`：有界事件缓冲与失败恢复、日志采样和结构化 logger。
- `enterprise-policy/src/runtime`：工作区路径策略与配置目录删除哨兵审计。
- `workbuddy-core/src/runtime`：不变量、序列化及 Cancellation/Promise 异步工具。
- `agent-ui/src/runtime`：会话消息、Tool 状态、Todo 计划投影和 Agent Team runtime 视图模型。
- `workbuddy-app/src/runtime`：应用配置、窗口状态、Conversation status 归一化和消息队列快照。
- `workbuddy-server/src/runtime`：本地 HTTP 路由、Session/Task 状态存储、Automation 调度、MCP 注册和 Artifact 索引。

## Server runtime 边界

`workbuddy-server/src/runtime` 将大型 daemon/app-server 快照中的稳定职责拆为可独立测试的模块：

- `session-store.js`：Session/Task 生命周期、终态保护和事件通知。
- `automation-scheduler.js`：Automation 注册、手动触发、定时触发和关闭。
- `mcp-registry.js`：MCP Server 注册、工具发现和调用转发。
- `artifact-index.js`：按 Session 查询 Artifact 元数据。
- `local-server.js`：无框架的本地 HTTP 路由容器。
- `connector-config.js`：将 marketplace Connector 条目按 MCP、CLI、Skill-only 类型规范化。
- `expert-manifest.js`：按 id 合并 Expert 清单，并解析 Expert 声明的 MCP 依赖。
- `version-compatibility.js`：Connector 与 WorkBuddy 版本的 semver 闭区间兼容判断。
- `poi-consent-registry.js`：MCP POI 注入授权的并发去重、超时拒绝和回传。
- `tool-routing.js`：Connector 工具路由优先级、连接状态降级、禁用过滤和 project/welcome 暴露策略。
- `expert-cache.js`：Expert manifest、版本、来源签名和 SHA-256 缓存管理。

这些模块只提供清晰的运行时边界，不宣称恢复了腾讯内部原始 TypeScript；发布程序仍使用 `src/source/` 中的证据快照。

## 运行与验证

```sh
npm run verify:structure
./scripts/run.sh
```

入口仍由 `scripts/run.sh` 启动 `extracted-app`，因此现有 Electron 行为不变；`packages/*` 是面向维护、检索和后续替换实现的模块化边界。`npm test` 会检查 13 个包、所有证据快照语法、恢复模块入口和 Agent 核心行为。
